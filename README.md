# dsh-plugin-rioterm

在 DeepSeek Harness 右侧栏打开 **Rio 终端**，使用当前会话工作目录中的交互式 shell。DSH 管理伪终端（PTY）、进程和屏幕快照；Rio WASM 负责显示内容和编码输入。它与内置终端并存，不接管 Agent 终端。

## 使用和验收

1. 在右侧栏选择 **＋ → Rio 终端**。出现 shell 提示符后，面板只显示终端，不留状态栏。点击终端，输入 `pwd` 并回车。这是用户终端：命令按 DSH 所在执行环境的系统用户权限运行，不经过 Agent 的审批流程。
2. 在 macOS/Linux 输入 `echo $$`，记下 shell PID。切换标签再切回，或刷新 DSH 页面，再执行一次；同一 Host 进程中应回到原来的 shell。开启默认自动聚焦时，点击切回已有的可输入 Rio 标签后，应能直接输入，无需再点击终端正文；可在两个 Rio 标签之间和其他类型标签之间分别验证。关闭终端标签会请求结束 shell，不等同于收起侧栏。Host 重启或进程已丢失时不会静默新建。
3. 输入 `stty size`，调整面板宽度后重试，列数应随之改变。拉高面板时，原有的滚动历史（包括空行）可能重新出现在顶部；插件不会为固定提示符的位置而删除历史。可用 `vim -Nu NONE -i NONE -n`（输入 `:q!` 退出）验证全屏程序。支持键盘、粘贴、文本选择和滚轮；当前不向 Vim 等应用转发鼠标点击或拖动。

**查找终端输出：** 在要搜索的 Rio 面板中点击放大镜，或在终端内按 `⌘F`（macOS）／`Ctrl+Shift+F`。输入文字后会高亮当前匹配；`Enter` 跳到下一处，`Shift+Enter` 跳到上一处，首尾循环，`Esc` 关闭查找。普通 `Ctrl+F` 保留给 shell 或终端应用；如果快捷键被 DSH 或系统占用，可在设置中开启搜索图标后点击放大镜。

右上角搜索图标默认完全隐藏，鼠标移入、聚焦或触屏操作均不会显示，使用 `⌘F`（macOS）／`Ctrl+Shift+F` 打开查找。只有在 **Rio 终端设置 → 交互 → 搜索图标常驻显示** 中开启开关后才显示图标。设置立即自动保存并同步到已打开的终端，不影响搜索快捷键，也不会收起已经打开的查找框。

查找区分大小写，按字面匹配当前标签的屏幕和仍保留的滚动历史；例如 `error[1]` 中的方括号无需转义。计数 `2 / 5` 表示当前是第 2 处；超过 1,000 处时显示 `1000+`，可缩小关键词范围。查找不会搜索其他标签或已丢弃的历史，不会向 shell 发送搜索词，也不需要取得输入控制权。

**使用中断线：**原画面会保留，但不能输入。DSH 的传输连接恢复后，原本可写且当前可见的 Rio 标签会尝试连接原来的 shell，用宿主快照恢复画面。隐藏标签等到再次显示才接屏幕；已经只读的窗口必须手动取得输入控制权。也可以点「重新连接」：已知终端身份时直接在原面板重连，不重新启动 shell，也不重发断线前未确认的输入。如果原进程已不存在，需要手动新建。

## Rio 设置

在 DSH 侧栏打开 **插件 → 已安装插件 → Rio 终端**。下拉选项、开关和取色器在选择后立即自动保存。选择框直接显示当前生效值；改过的选项在标题后显示轻量的「恢复默认＋图标」动作，恢复后重新跟随默认值，不会把展示的默认值保存成个人配置。内边距的恢复动作位于组标题后，仅移除四个方向的个人覆盖。设置列表中的字体、数值和颜色输入在停止输入约 600 毫秒或离开输入框时保存，无需点「保存」。无效输入只留在草稿里，其他有效设置仍可保存。标题旁用图标提示等待、保存中和保存成功，异常时显示文字说明；减少动态效果时使用静态图标。页头右上角的「恢复默认设置」需要再次确认。这些设置只影响 Rio 标签，不改变 DSH 的内置终端。

字体与布局、终端配色的预览独立放在各分组顶部：前者显示字体样张，后者展示文字、ANSI 颜色、粗体、选区与光标。预览随有效草稿即时更新，无需打开终端。

| 设置         | 行为                                                                                                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 字体、字号   | 两项分别继承 **DSH 设置 → 通用 → 更多字体设置** 中的终端配置。只改字号不锁定字体；清空其中一项，就重新跟随对应的宿主设置。字体只使用本机字体列表。                         |
| 配色         | 每个颜色可单独覆盖；清空只移除当前覆盖，不会把当时看到的颜色固定下来。来源见下表。                                                                                         |
| 渲染器       | 默认使用 DOM。可切换 Canvas，在 Canvas 下选择光标形状，或开启预测反馈并设置延迟阈值和标记样式。预测默认关闭；开启时，未确认的字符只画占位符，字符本身仍以 shell 回显为准。 |
| 终端留白     | 上、右、下、左可分别设为 0–64 px，默认 16 / 8 / 8 / 8，与内置终端对齐。四边设为 0 即恢复贴边。启用自动适配时，只用扣除留白后的空间计算行列数。                             |
| 面板行为     | 打开或切回 Rio 标签时，默认自动聚焦可输入的终端，无需再点面板。可在此关闭自动聚焦；更改设置本身不会移动焦点。关闭自动适配尺寸则保留宿主网格。                              |
| 键盘和链接   | 可切换 Alt 作为 Meta，以及纯文本 URL 识别。普通单击不打开链接；Ctrl / ⌘ 加点击会先显示目的地址，确认后才打开网页或邮件链接。                                               |
| 本地滚动历史 | 留空使用 DSH 告知的上限，`0` 表示不保留。新上限在下一次创建或从宿主快照恢复屏幕时生效，不为了应用设置丢弃现有历史。                                                        |

**想让 `ls` 的粗体目录名更接近内置终端？** 在「终端配色」中把「ANSI 调色板」选为「DSH 内置终端」，「粗体使用亮色」保留「跟随调色板」。这样普通蓝仍用基础蓝，粗体蓝会用亮蓝。使用「Rio 默认」调色板时，默认只加粗，不换色；也可以独立选「始终开启」或「始终关闭」。选择会自动保存，并更新已经打开的 Rio 终端。

粗体映射只影响前景的基础 8 个 ANSI 色位；例如自定义过亮蓝，就使用你的亮蓝。背景色、显式指定的亮色和 RGB 真彩色不会因此加亮。DSH 内置终端另外使用 4.5 的最低对比度，本选项不会模拟它，所以两边的最终观感不保证完全一致。

可在两个终端分别运行以下命令比较，不依赖 `ls` 的主题：

```sh
printf '\033[34m普通蓝\033[0m  \033[1;34m粗体蓝\033[0m  \033[94m亮蓝\033[0m\n'
```

**设置文字与背景：** 在「终端配色」顶部直接选择文字色、背景色，或输入十六进制色值；两项可以独立修改。取色立即保存，手动输入在停止输入约 600 毫秒或离开输入框后保存。点击对应颜色标题后的「恢复默认」即可移除该项个人覆盖并恢复继承，不影响其他颜色。光标和选区颜色放在「自定义光标与选区」折叠区。

点击色块打开与设置页圆角一致的取色弹层，可拖动色盘、调节色相和不透明度，或输入 RGB。弹层内的 HEX 按 Enter、离开输入框或明确关闭时提交有效值；Escape 丢弃尚未提交的 HEX 文本，不撤销已经保存的选择。三／六位 HEX 表示不透明，四／八位包含 alpha；其他取色操作保留原 alpha。平台支持时可使用「屏幕取色」，取消不会改变设置。

**配色从哪里继承？** 先看你为这一项保存的值，再看当前 DSH 配置中为 **Rio 插件**预设的值；两者都没有时，才使用下列默认来源。不是从旁边的 DSH 内置终端复制一套主题。

| 颜色               | 没有 Rio 覆盖时的来源                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| 文字、背景         | DSH 界面的主文字色、基础背景色，随 DSH 主题变化。                                                 |
| 光标               | Rio 最终使用的文字色；例如只把文字改为绿色，未单独设置的光标也会跟着变绿。                        |
| 选中文字、选区背景 | 浏览器提供的系统选区色 `HighlightText`、`Highlight`，不是 DSH 的强调色。                          |
| ANSI 16 色         | 所选的 ANSI 调色板：默认使用 `rioterm`；也可选 DSH 内置终端的 xterm 16 色预设。每个色位独立继承。 |

改变显示设置不会新建 shell，也不会重新连接当前终端。行列数和单元格像素尺寸由宿主与渲染器协商，不当作可手填的显示参数；真实 PTY 的换行处理也不修改。验收字体继承时，可以打开已有 Rio 标签，仅覆盖字号，然后在 DSH 中换终端字体；字体应随宿主更新，字号应保持 Rio 的值。

## 本地开发

插件注册、React 页面、会话管理与 Rio 渲染分开维护。修改前可从[终端模块边界与测试索引](.agents/specs/terminal-modules.md)找到对应入口。

使用 pnpm，在仓库根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test
```

React 界面使用 Tailwind CSS v4 和仓库内的 shadcn/ui 组件。只为 Rio 面板、引导和插件设置区编译样式，不加载 CDN，不给 DSH 页面引入 Preflight；主题色直接引用 DSH 的语义色。修改样式与控件时见[UI 约定](.agents/specs/terminal-modules.md#ui-样式与组件)。

`pnpm typecheck` 使用锁定版本的 tsrs，以 `--noEmit` 检查源码与构建配置。`pnpm check` 先运行 Biome，再运行相同的类型检查。`pnpm build` 用 tsdown 打包客户端，用 `tsc --noCheck`（通过 Host 配置）仅转译宿主入口，并把与 JS 版本匹配的独立 WASM 复制到 `lib/`。`pnpm test` 在构建后运行。

粗体亮色是渲染设置，不会改写 PTY 输出或 WASM 网格。仓库通过 [rioterm 渲染补丁](patches/rioterm@0.1.8.patch)给锁定版本的 DOM 和 Canvas 渲染器加入同一条颜色解析规则；升级 `rioterm` 时需检查上游是否已支持该选项，并运行渲染测试。

本地试用时先构建，再到 DSH 的插件管理中添加当前仓库目录。插件不依赖 CDN；如果页面策略阻止 WASM 编译，请检查错误提示，不要关闭安全策略。

另有仅用于开发的 POSIX 真机冒烟测试（需要已安装的 DSH、Vim 和系统授权分配 PTY，在工作区根目录运行）：

```sh
ELECTRON_RUN_AS_NODE=1 "$DSH_NODE_EXECUTABLE" scripts/test-dsh-pty.mjs
```

该测试使用独立的 DSH 控制器与测试 shell，不连接正在运行的用户终端。若系统不允许分配 PTY，可单独验证桌面控制器与 Rio 是否兼容：

```sh
ELECTRON_RUN_AS_NODE=1 "$DSH_NODE_EXECUTABLE" --test tests/dsh-desktop-loopback.test.mjs tests/desktop-reconnect.test.mjs tests/host-preferences-desktop.test.mjs
```

回环测试不启动子进程：使用真实的 DSH 控制器和屏幕序列化器、插件的输入协议和 Rio WASM，检查中文输入、尺寸、全屏模式重连以及还原主屏幕。重连测试使用桌面自带的 Gateway，模拟传输断开、恢复与手动接管，检查没有重建 shell 或重复发送输入。桌面设置测试使用真实的 Cordis Loader 与 DSH 配置服务，验证保存和清除覆盖不会重新挂载插件；配置写入在内存中，不触及个人配置。常规 `pnpm test` 在普通 Node 中会跳过这三项桌面专测。它们不替代 GUI 里的人工验收。

## 变更集与发布

本地与 CI 使用 Semifold 0.3.4。需要发版的改动应随代码提交变更集，例如：

```sh
semifold commit --name fix-resize --package dsh-plugin-rioterm=patch --tag fix --summary '修复终端尺寸同步。'
semifold config sync --check
semifold status
```

提交到 `main` 的 PR 会运行质量检查并展示版本计划。推送到 `main` 后，相同的质量检查通过才运行 `semifold ci`：有变更集时，自动更新 `release` → `main` 的版本 PR；合并版本 PR 后，自动创建 GitHub Release。`release` 分支由 Semifold 管理，请勿手动开发。

当前工程骨架仅通过 GitHub 记录版本，**不发布到 npm**，也不需要 npm Token。启用远端自动化时，请在 GitHub 仓库设置中允许 GitHub Actions 创建 PR，并允许发布任务写入仓库内容。
